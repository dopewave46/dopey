DopeOrca OS · Version 1 · Locked visual language

DopeOrca OS Design System

The permanent visual foundation for DopeOrca OS — the internal operating system for DopeOrca Technologies, Mumbai. This document locks the design tokens and component style guide that every later screen must follow exactly.

Premium, minimal, technical, confident. Crimson creates focus; white and neutral surfaces carry the interface. Light theme only in Version 1 — no dark mode, no theme toggle, no dark tokens. No page may introduce a colour, font, spacing value, radius, shadow, or component pattern outside what is defined here.

01 — Principles & usage

How this system is meant to feel

The interface should read as a serious technology product — in the spirit of Linear, Stripe, Notion, and Vercel — without copying any of their branding or layouts. It is an original DopeOrca identity.

Should feel

  • Premium, modern, minimal, intelligent
  • Professional, clean, confident, technical
  • Organised, fast, immediately understandable

Must never feel

  • Cheap, generic, over-designed, cartoonish
  • Cluttered or excessively colourful
  • Like an admin template, an accounting app, or an old enterprise dashboard

Colour balance target

White / neutral surfaces are dominant. Charcoal carries typography. Crimson is reserved for brand and important actions. Grey supports. Crimson should account for only a small fraction of any screen — it creates focus, it does not fill the interface.

06 — Shadow scale

Soft, low-opacity depth

Cards rely first on white surface + hairline border, then a very subtle shadow. Heavy shadows are never used. Only modals and drawers use the largest elevation.

Extremely clean, sectioned when complex

21 — Motion & hover

Fast, smooth, purposeful

  • Durations: 120ms for hovers and small state changes, 180ms for modals, drawers, dropdowns, sidebar. Easing cubic-bezier(.2,.7,.3,1).
  • Motion is allowed for: page transitions, hover states, opening modals / dropdowns, sidebar collapse, progress changes.
  • Never: bouncing, large zooms, parallax, looping or ambient movement, attention-seeking effects.
  • Hover: buttons shift colour/depth subtly; interactive cards lift 2px with --sh-md; table rows take a --crimson-tint background; links show the crimson accent.
  • All motion respects prefers-reduced-motion — transitions collapse to near-instant.
22 — Accessibility

Built into the tokens, not bolted on

  • Body text (--charcoal / --slate) on white clears WCAG AA; --muted is reserved for non-essential metadata only.
  • Every focusable control shows the crimson focus ring on :focus-visible.
  • Minimum body size 14px; labels 12px with adequate weight and contrast.
  • Status is never colour-only — badges carry a dot and a text label; validation carries an icon and a message.
  • Icons always pair with text in navigation and actions; icon-only buttons carry an aria-label.
  • Interactive targets are at least 34px; hit areas extend to padding.

24 — Consistency & governance

This system is locked

Every later prompt — application shell, dashboard, CRM, projects, finance, analytics, tasks, maintenance — references and follows this document exactly.

  • No page introduces a new colour, font, font weight, spacing value, radius, shadow, or component pattern outside what is defined here.
  • These never change between pages: fonts, button styles, border radius, card design, colours, icon style, spacing, table styling, form styling, status badges.
  • Components are built once and reused: buttons (4 variants), inputs / forms, cards (standard + metric), tables, badges, modals, drawers, sidebar (+ icons), header (clock / search / notifications / avatar), charts, progress, activity timeline, empty / loading / error states, notifications.
  • Dark mode is explicitly out of scope for Version 1 — no theme toggle, no dark tokens.
  • Any change to a token or component is a change to this document first, then propagated everywhere.

Locked reference. Prompt 03 onward builds screens using only these tokens and components. No business logic, backend, database, or authentication is part of this design-system prompt.
